Nexora — Project Overview
1. Purpose

Nexora is a simulated B2B SaaS platform used to practise technical product support investigations.

The project demonstrates how a support engineer can reproduce reported problems, inspect REST API responses, query relational data, identify discrepancies, and prepare evidence-based findings for engineering teams.

All products, customers, records, and incidents in this project are fictional.

2. Product Scenario

Nexora provides business customers with functionality to manage:

Customer records
Orders and payment records
User accounts and role-based permissions
External integrations
Webhook events and processing status

The simulated environment will include API endpoints, a relational database schema, test records, and documented support investigations.

3. Technical Scope
REST API fundamentals and HTTP status codes
API requests, JSON payloads, and response inspection
API testing with Postman
SQL filtering, aggregation, joins, and NULL handling
Investigation of order and payment discrepancies
Authentication and authorization troubleshooting
Evidence collection and engineering escalation
Incident reports, troubleshooting procedures, and knowledge-base documentation

5. Investigation Workflow
Record the reported issue and expected behaviour.
Reproduce the issue where possible.
Inspect the relevant API request and response.
Query the database to validate the affected records.
Determine the scope of the issue and identify confirmed discrepancies.
Document findings, limitations, and recommended next steps.
Prepare an engineering escalation when required.

7. Planned Deliverables
Database schema and fictional test data
SQL investigation query library
Postman collection
API investigation notes
Incident case studies
Troubleshooting runbook
Knowledge-base articles
Engineering escalation templates

9. Project Integrity

This is an independent learning and portfolio project, not a production SaaS application. Simulated scenarios do not represent real customer incidents or professional employment experience.

Only implemented, tested, and documented capabilities will be described as completed work.
